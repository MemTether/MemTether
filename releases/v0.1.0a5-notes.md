## v0.1.0a5 — CLI 参数与治理模块加载路径修正

相对 **v0.1.0a4**（tag `8f2c69f`）。本版全部是缺陷修复，无新功能。

### 修复

- **`gateway.py qvalue` 不接受 `--source`**：原先只有 `--agent`，而 `AGENTS.md` /
  `HARD-RULES.md` 的约定是 `--source`，照文档写会被 argparse 直接打回 exit 2。
  现改为多选项字符串别名，两种写法等价、`dest` 不变，旧调用方零影响。
- **`gateway.py record_tool` 没有 `--source`**：分发处只能落默认来源，调用方
  无法指定归属。已补参数并透传。
- **`gateway.py retire` 没有 `--source`，且函数体漏掉来源校验**：`retire()` 此前是
  唯一不调用 `_guard_source()` 的写入函数，`by_agent` 可直穿审计日志。两处都补。
- **`gateway.py` / `memsearch.py` 共 6 处裸 `import governance`**：新增
  `_load_governance()`，改为按显式文件路径加载，杜绝仓库外同名模块遮蔽导致
  连到错误库（对应事故档案 #10 的遗留半边）。
- **`_count_active_facts()` 只统计 facts 不统计 tool_assets**：facts 为 0 而资产
  非空时会误报「空库」，把诊断方向带偏。已改为两表相加。
- **stdout 未按 UTF-8 重配导致只读视图崩溃**：`gateway.py qvalue`（不带参数）与
  `peer_msg.py read` 在 GBK 控制台下遇 GBK 编不出的字符直接 `UnicodeEncodeError`。
  新增 `_fix_stdio()` 在入口重配。
- **`scripts/scan_leaks.py` 自身会崩**：该脚本是发布前泄密闸门，原先崩在 `report()`
  并返回 exit 1，会被误读成「发现泄密」而真相是根本没扫完。

### 验证

- `scripts/check_packaging.py`：59 个根模块 + 包清单 + 入口 + 版本 `0.1.0a5` 全对齐
- 干净目录 `pip install --target` 后冒烟：`qvalue` 只读与 `--source` 两种写法、
  `record_tool --source`、`retire --source`、治理五命令（govern / conflicts /
  conflicts_exact / selfcheck / stale）全部 exit 0
- wheel 内 `gateway.py` 与仓库源文件 sha256 一致
- `scripts/scan_leaks.py`（`MEM_SCAN_TERMS` 指向真源词表）BLOCK 0 命中

### 兼容性

无破坏性变更：`--agent` 仍可用；`MEM_DB` / `MEM_PROJ_PATH` 语义不变。
